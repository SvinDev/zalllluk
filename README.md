# УК Онлайн

Платформа для управляющих компаний: жилфонд и лицевые счета, приём показаний счётчиков
(в том числе автоматически по API), начисления и квитанции с QR-кодом для оплаты,
заявки жителей, пропуска для гостей и автомобилей, объявления.

Один экземпляр системы обслуживает одну УК (отдельная база данных на клиента —
простая изоляция данных и реквизитов).

## Возможности

| Раздел | Что умеет |
|---|---|
| **Жилфонд** | Дома, помещения с лицевыми счетами, площадью и числом проживающих, привязка жителей к помещениям |
| **Счётчики** | Реестр приборов учёта (ХВС, ГВС, электроэнергия, отопление, газ), сроки поверки, история показаний с расходом, контроль «не передали показания в этом месяце» |
| **Показания** | Житель передаёт в кабинете, сотрудник вносит задним числом; проверка монотонности относительно соседних показаний, защита от гонок блокировкой строки счётчика |
| **Интеграции** | **Push**: внешняя система (АСКУЭ, IoT-шлюз) отправляет пакеты показаний по API-ключу, повторы идемпотентны. **Pull**: сервер сам опрашивает внешние источники по расписанию, инкрементально, с курсором |
| **Начисления** | Тарифы по площади / по жильцам / по счётчику / фиксированные, для всех домов или конкретного дома. Расчёт черновиков за месяц → проверка → выставление |
| **Квитанции** | Печатная форма с реквизитами, показаниями «было → стало», долгом прошлых периодов и QR-кодом по ГОСТ Р 56042-2014 (сканируется банковскими приложениями) |
| **Оплаты** | Регистрация по помещению или номеру л/с, защита от двойного учёта по номеру документа, разнесение по квитанциям от старых к новым (FIFO), переплата учитывается в следующих квитанциях. Отчёт по должникам |
| **Заявки** | Категории и приоритеты с нормативными сроками (SLA), исполнители, переписка с внутренними комментариями, история статусов, подтверждение и оценка жителем |
| **Пропуска** | Гостевые, автомобильные, доставка; разовые до суток оформляются сразу, остальные — после согласования. Пост охраны: проверка по коду или госномеру (латиница/кириллица/пробелы не важны) и отметка прохода |
| **Объявления** | Для всех домов или одного дома, закрепление, отложенная публикация |
| **Сводка** | Открытые и просроченные заявки, общий долг, охват показаний за месяц, начислено/оплачено за полгода, счётчики с истекающей поверкой |

### Роли

| Роль | Доступ |
|---|---|
| Администратор | Всё, включая сотрудников и интеграции |
| Управляющий | Жилфонд, жители, счётчики, заявки, пропуска, объявления |
| Бухгалтер | Тарифы, начисления, квитанции, оплаты, должники |
| Охрана | Пост охраны и пропуска |
| Житель | Свои помещения: показания, квитанции и оплата по QR, заявки, пропуска, объявления |

Жителю чужие данные недоступны на уровне API: запрос к чужому помещению,
счётчику, квитанции или заявке возвращает 404.

## Быстрый старт (Docker)

```bash
cp .env.example .env        # задайте SECRET_KEY и реквизиты УК
docker compose up -d --build
docker compose --profile demo run --rm seed   # демо-данные (по желанию)
```

- Веб-кабинет: http://localhost:8080
- Документация API (Swagger): http://localhost:8080/api/docs

Демо-доступы (пароль у всех `demo12345`):

| Email | Роль |
|---|---|
| admin@demo.ru | администратор |
| manager@demo.ru | управляющий |
| buh@demo.ru | бухгалтер |
| guard@demo.ru | охрана (гостевой пропуск `GST7K2` действует 10 часов после загрузки демо) |
| resident@demo.ru | житель |

Без демо-данных создайте администратора:

```bash
docker compose run --rm api python -m app.cli create-admin --email admin@uk.ru --name "Иван Иванов"
```

## Локальная разработка

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/), Node.js 22 и PostgreSQL 16.

```bash
make install                   # зависимости бэкенда и фронтенда
cp backend/.env.example backend/.env
make migrate && make seed      # схема БД и демо-данные
make dev-api                   # API на :8000 (Swagger: /api/docs)
make dev-web                   # фронтенд на :5173, /api проксируется на :8000
```

Остальные команды — `make help`. Тесты бэкенда ходят в отдельную БД
(`uk_test`, переопределяется `TEST_DATABASE_URL`); каждый тест выполняется
в транзакции, которая откатывается.

После изменения API обновите типы фронтенда — `make openapi`. CI проверяет,
что `frontend/openapi.json` и `src/api/schema.d.ts` соответствуют бэкенду.

## Архитектура

```
backend/                      FastAPI, SQLAlchemy 2 (async), PostgreSQL, Alembic
  app/core/                   настройки, БД, безопасность, ошибки, пагинация
  app/<модуль>/               models · schemas · service · router
    users, auth, housing      пользователи, роли, дома и помещения
    meters, integrations      счётчики, показания, push/pull-интеграции
    billing                   тарифы, расчёт, квитанции, оплаты, QR
    tickets, passes           заявки, пропуска
    announcements, dashboard  объявления, сводка
  app/cli.py                  create-admin, seed-demo, openapi
  alembic/                    миграции
  tests/                      интеграционные тесты API на реальном PostgreSQL

frontend/                     React 19, TypeScript, Ant Design 5, TanStack Query
  src/api/                    типизированный клиент из OpenAPI (openapi-fetch)
  src/auth/                   контекст авторизации и защита маршрутов по ролям
  src/pages/                  страницы, загружаются лениво
```

Бизнес-логика живёт в `service.py` модулей, роутеры — тонкие. Деньги и показания —
`Decimal`/`NUMERIC`, в JSON передаются строками, без потерь на плавающей точке.

## Интеграция показаний счётчиков

Счётчик определяется по заводскому номеру (`serial_number`) или идентификатору
во внешней системе (`external_id`, задаётся в карточке счётчика).

### Push: внешняя система отправляет показания

Ключ выпускается в разделе «Интеграции» (показывается один раз, хранится только хэш).

```http
POST /api/v1/integrations/readings
X-API-Key: ukapi_xxxxxxxx_...
Content-Type: application/json

{
  "readings": [
    {"external_id": "iot-100001-electricity", "value": "1234.567", "taken_at": "2026-09-25T10:00:00+03:00"},
    {"serial_number": "ХВ-100001", "value": "389.120", "taken_at": "2026-09-25T10:00:00+03:00"}
  ]
}
```

До 1000 записей в пакете, `taken_at` — обязательно с часовым поясом. Ответ — отчёт:

```json
{"received": 2, "accepted": 1, "duplicates": 1,
 "rejected": [{"index": 1, "serial_number": "ХВ-100001", "external_id": null, "error": "..."}]}
```

Повторная отправка того же показания (счётчик + момент + значение) считается дублем,
а не ошибкой — запрос можно безопасно ретраить. Ошибка в одной записи не отменяет остальные.

### Pull: сервер опрашивает внешнюю систему

В разделе «Интеграции» добавляется источник с URL и (опционально) Bearer-токеном.
Сервер раз в `METER_SYNC_INTERVAL_MINUTES` выполняет:

```http
GET <url>?since=2026-09-25T10:00:00+00:00
Authorization: Bearer <token>
```

и ожидает ответ в том же формате `{"readings": [...]}`. Параметр `since` — максимальный
`taken_at` из предыдущей выгрузки (при первом опросе отсутствует). При нескольких
репликах API опрос выполняет только одна (advisory lock в PostgreSQL).

Для конкретного поставщика с собственным форматом достаточно добавить класс
в `app/integrations/providers.py`, реализующий `fetch(since)`.

## Правила начислений

- Период — календарный месяц в часовом поясе УК (`TIMEZONE`, по умолчанию Europe/Moscow).
- Тариф применяется к месяцу, если действует на его первое число — смена ставки
  «с 1 июля» не даёт двойного начисления.
- Коммунальные услуги по счётчикам (по мотивам ПП РФ № 354):
  1. есть показания в месяце — по факту от последних учтённых показаний;
  2. нет показаний — по среднемесячному расходу (история не короче 3 месяцев в окне
     6 месяцев), но не дольше 3 периодов подряд;
  3. иначе — по нормативу × число проживающих (так же, если счётчика нет);
  4. когда показания появляются, начисленное «по среднему/нормативу» снимается
     отдельной строкой перерасчёта ровно на ранее начисленные суммы.
- Повторный расчёт пересчитывает только черновики; выставленные квитанции не меняются.
  Ошибочную выставленную квитанцию можно аннулировать — оплаты перераспределятся.
- Срок оплаты — до 10-го числа следующего месяца (ст. 155 ЖК РФ).

## Конфигурация

Все параметры — переменные окружения (см. `.env.example` и `backend/.env.example`):
`DATABASE_URL`, `SECRET_KEY` (в production обязателен свой), `ACCESS_TOKEN_TTL_MINUTES`,
`CORS_ORIGINS`, `TIMEZONE`, `METER_SYNC_*`, реквизиты УК `COMPANY_*` для квитанций и QR.
